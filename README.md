# Raw pointers и references в Rust

## Что демонстрирует код

Пример показывает **разницу** между **безопасными ссылками** (`&T`, `&mut T`) и **сырыми указателями** (`*const T`, `*mut T`). Через сырой указатель напрямую изменяется элемент `Vec` **без проверок** границ — это **`unsafe`** и **потенциально опасно**.

```rust
fn main() {
    let mut v = vec![1, 2, 3];
    println!("Before: {:?}", v);   // [1, 2, 3]

    let p_v = v.as_mut_ptr();       // *mut i32

    unsafe {
        *p_v.add(1) += 1;           // изменяем v[1]
    }

    println!("After: {:?}", v);    // [1, 3, 3]
}
```

## Что происходит по шагам

### 1. Создание `Vec`

```rust
let mut v = vec![1, 2, 3];
```

- `v` — `Vec<i32>` с элементами `[1, 2, 3]`.
- `mut` — нужен, потому что будем **изменять**.

### 2. Получение сырого указателя

```rust
let p_v = v.as_mut_ptr();   // *mut i32
```

- **`as_mut_ptr()`** — метод `Vec`, возвращающий **`*mut i32`**.
- **Без `unsafe`** — создание указателя безопасно.
- `p_v` указывает на **первый элемент** массива `v`.

### 3. Изменение через указатель

```rust
unsafe {
    *p_v.add(1) += 1;
}
```

- **`p_v.add(1)`** — **арифметика указателя**: сдвиг на **1 элемент** (`i32` = 4 байта).
- **`*...`** — **разыменование**.
- **`+= 1`** — **увеличение** значения на 1.
- **`unsafe`** — обязателен для разыменования и арифметики указателей.

**Результат:** `v[1]` было `2`, стало `3`.

### 4. Вывод

```rust
println!("After: {:?}", v);   // [1, 3, 3]
```

## Ссылки (`&T`, `&mut T`) vs сырые указатели (`*const T`, `*mut T`)

### Ссылки — безопасные

```rust
let mut v = vec![1, 2, 3];

// Неизменяемая ссылка
let r: &i32 = &v[1];
println!("{}", r);   // 2

// Изменяемая ссылка
let mr: &mut i32 = &mut v[1];
*mr += 1;
println!("{:?}", v);   // [1, 3, 3]
```

**Плюсы ссылок:**

- **Проверка границ** — `v[1]` паникует при выходе за пределы.
- **Borrow checker** — гарантирует корректность.
- **Нет `unsafe`**.
- **Автоматическое разыменование** — `r` работает как значение.

### Сырые указатели — небезопасные

```rust
let mut v = vec![1, 2, 3];
let p = v.as_mut_ptr();

unsafe {
    *p.add(1) += 1;   // без проверок
    *p.add(100) += 1; // ❌ UB — выход за границы!
}
```

**Минусы сырых указателей:**

- **Нет проверки границ** — можно выйти за пределы → **UB**.
- **Нет проверки на `null`**.
- **Нет проверки выравнивания**.
- **Нет borrow checker**.
- **Требуют `unsafe`**.

## Сравнительная таблица

| | Ссылки `&T` / `&mut T` | Сырые указатели `*const T` / `*mut T` |
|---|---|---|
| **Безопасность** | ✅ Гарантирована | ❌ Ответственность на программисте |
| **Проверка границ** | ✅ Да | ❌ Нет |
| **Проверка `null`** | ✅ Не бывает | ❌ Может быть |
| **Проверка выравнивания** | ✅ Да | ❌ Нет |
| **Borrow checker** | ✅ Да | ❌ Нет |
| **`unsafe`** | ❌ Не нужен | ✅ Нужен для разыменования |
| **Арифметика** | ❌ Нельзя | ✅ `add`, `offset`, `wrapping_add` |
| **Владение** | Заимствование | Не отслеживается |
| **`Send`/`Sync`** | Зависит от `T` | ❌ Не реализуют автоматически |

## Когда использовать ссылки

**Почти всегда** — это **идиоматичный** Rust:

```rust
// ✅ Чтение
fn sum(v: &[i32]) -> i32 {
    v.iter().sum()
}

// ✅ Изменение
fn double(v: &mut [i32]) {
    for x in v.iter_mut() {
        *x *= 2;
    }
}

// ✅ Возврат ссылки
fn first(v: &[i32]) -> Option<&i32> {
    v.first()
}
```

## Когда использовать сырые указатели

**Только** когда **ссылки не подходят**:

### 1. FFI (взаимодействие с C)

```rust
extern "C" {
    fn malloc(size: usize) -> *mut u8;
    fn free(ptr: *mut u8);
}

unsafe {
    let p = malloc(1024);
    if !p.is_null() {
        *p = 42;
        free(p);
    }
}
```

### 2. Ручное управление памятью

```rust
use std::alloc::{alloc, dealloc, Layout};

unsafe {
    let layout = Layout::new::<i32>();
    let p = alloc(layout) as *mut i32;
    *p = 42;
    dealloc(p as *mut u8, layout);
}
```

### 3. Низкоуровневые структуры данных

```rust
struct Node {
    value: i32,
    next: *mut Node,
}
```

### 4. Обход borrow checker (осторожно!)

```rust
// Иногда нужно, когда несколько частей структуры
// заимствуются одновременно
unsafe {
    let p = &mut data as *mut Data;
    let a = &mut (*p).field1;
    let b = &mut (*p).field2;
}
```

### 5. Оптимизация (редко)

Когда **профилирование** показало узкое место и **ссылки** не подходят.

## `Vec::as_mut_ptr` и альтернативы

### `as_mut_ptr` — сырой указатель

```rust
let mut v = vec![1, 2, 3];
let p = v.as_mut_ptr();   // *mut i32

unsafe {
    *p.add(1) += 1;
}
```

### `as_mut_slice` — безопасный срез

```rust
let mut v = vec![1, 2, 3];
let s = v.as_mut_slice();   // &mut [i32]

s[1] += 1;   // ✅ без unsafe, с проверкой границ
```

### `get_mut` — безопасный доступ

```rust
let mut v = vec![1, 2, 3];
if let Some(x) = v.get_mut(1) {
    *x += 1;   // ✅ безопасно
}
```

### `iter_mut` — безопасный перебор

```rust
let mut v = vec![1, 2, 3];
for x in v.iter_mut() {
    *x += 1;
}
```

**Все три безопасных варианта дают то же самое**, но **без `unsafe`** и **с проверками**.

## Опасности сырых указателей

### 1. Выход за границы

```rust
let mut v = vec![1, 2, 3];
let p = v.as_mut_ptr();

unsafe {
    *p.add(100) = 42;   // ❌ UB — выход за границы
}
```

### 2. Висячий указатель

```rust
let p: *const i32;
{
    let x = 42;
    p = &x;
}   // x уничтожен
unsafe {
    println!("{}", *p);   // ❌ UB — use after free
}
```

### 3. `null`

```rust
let p: *const i32 = std::ptr::null();
unsafe {
    println!("{}", *p);   // ❌ UB — null dereference
}
```

### 4. Гонки данных

```rust
let mut v = vec![1, 2, 3];
let p = v.as_mut_ptr();

// Два потока одновременно пишут через p
// ❌ data race → UB
```

### 5. Неправильное выравнивание

```rust
let p = 0x1 as *const i32;
unsafe {
    println!("{}", *p);   // ❌ UB — misaligned
}
```

## Безопасные альтернативы

| Задача | Сырой указатель | Безопасная альтернатива |
|---|---|---|
| Доступ к элементу | `*p.add(i)` | `v[i]` или `v.get(i)` |
| Изменение элемента | `*p.add(i) = x` | `v[i] = x` или `v.get_mut(i)` |
| Перебор | `*p.add(i)` в цикле | `for x in &v` / `&mut v` |
| Срез | `slice::from_raw_parts(p, n)` | `&v[..]` |
| Копирование | `ptr::copy` | `slice::copy_from_slice` |

## Итог

### Ссылки (`&T`, `&mut T`)

- **Безопасны** — проверки границ, `null`, выравнивания.
- **Borrow checker** — гарантирует корректность.
- **Без `unsafe`**.
- **Идиоматичны** — используйте **по умолчанию**.

### Сырые указатели (`*const T`, `*mut T`)

- **Небезопасны** — нет проверок.
- **Требуют `unsafe`** для разыменования.
- **Арифметика** — `add`, `offset`, `wrapping_add`.
- **Использовать** — FFI, ручное управление памятью, низкоуровневые структуры.
- **Избегать** — если есть **безопасная** альтернатива.

### В вашем коде

- **`v.as_mut_ptr()`** — сырой указатель.
- **`*p_v.add(1) += 1`** — изменение через указатель **без проверок**.
- **`unsafe`** — потому что разыменование и арифметика указателей небезопасны.
- **Эквивалент без `unsafe`**: `v[1] += 1` или `v.as_mut_slice()[1] += 1`.
- **Правило:** используйте **ссылки**, где возможно; сырые указатели — **только** когда **действительно** нужно.
